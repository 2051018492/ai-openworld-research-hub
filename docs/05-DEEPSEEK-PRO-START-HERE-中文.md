# 云端 DeepSeek Pro｜研究接棒说明

## 本仓库的作用

这是公开的技术研究与交流仓库，不是主应用的源码仓库。请首先阅读本仓库 [README](../README.md)，并使用其公开内容进行研究；**不拥有私有仓库读取权限不是故障，也不意味着可以绕过访问控制**。

## 当前目标

系统审计 SillyTavern 的角色卡、世界书、Prompt Manager、群聊、STscript/变量、上下文与长期记忆、Swipe/分支和插件架构；研究状态栏/追踪插件，并比较三种方案：

- A. 基于 SillyTavern 二次开发一个开放世界运行系统；
- B. 保留我们既有的独立世界引擎，合法复用成熟模块；
- C. 混合结构：SillyTavern 的角色聊天界面结合独立世界事件引擎。

分析源码依赖、实际持久化能力、回滚、知识边界、许可证、移动端、私人服务器部署与安全问题。具体交付与可重复测试说明见 [研究任务](02-SILLYTAVERN-RESEARCH.md)。

## 如何交付

- 如果具备 GitHub 写权限：在**独立研究分支**添加 `docs/research/` 下的 Markdown 报告，发 PR，不自动合并。
- 如果只有公开读取权限：在云端工作区生成 Markdown 文件交用户上传；也可以使用公开仓库 Issues（如该环境支持）。
- 每项结论标记「作者文档声称」「源码核验」「已运行实测」「待验证」，附具体开源提交 SHA、文件路径、函数和测试日志。
- 阅读私有项目实际代码必须由用户**另外提供审查过的源码包**，不能因为这个研究仓库公开就假设能访问私有应用代码。

## 绝对边界

1. 不公开私有代码、密钥、服务器 IP、真实聊天或真实数据、未经检查的截图及旧 Git 历史。
2. 不修改或推送私有仓库，不影响 Astra 正在进行的 V0.6；不进入腾讯云生产服务器。
3. 不未经授权调用计费模型、公开部署、合并 PR。
4. 不直接复制不兼容许可证的第三方代码；SillyTavern 本体和插件分别核验。
5. REA 是可选动态研究手段。开源代码优先静态审查，动态实验需隔离且安全可审计。

## 提醒

你负责提供**研究证据与方案建议**，不负责最终决定迁移和开始正式开发。产品方向由主脑对话与用户决定，执行流程另行批准。
