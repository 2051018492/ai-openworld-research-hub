# Public Research Hub — Contribution and Safety Rules

This repository is a public **technical research** inbox, not the private application repository. Use Issues for questions or findings and PRs for reviewable Markdown reports.

## In scope

Open-source source-path/function investigations, dependency analysis, compatible-license reports, neutral architecture comparisons, sanitized minimal experiments, reproducible tests and proposals.

## Out of scope

Unreleased private code, API tokens or keys, account numbers, private conversations, internal service IPs/domains, screenshots with personal data, databases, private Git histories, large third-party code dumps, or unapproved production deployments.

## Submission checklist

1. Cite exact project versions and commit SHAs.
2. Distinguish README/documentation promises from source-verified findings and runtime tests.
3. Check transitive dependency and original file licenses before suggesting code reuse.
4. Prefer fake providers and fixtures over paid-model tests.
5. Place work in a separate research branch and submit PRs for review; never change the private application's working branch.
6. If a secret is encountered, do **not** publish it in an issue—inform the maintainer privately.

Decisions are made in the separate main-brain workflow. Research contributions are not implementation authorization.
